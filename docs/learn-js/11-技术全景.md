# 11 · 技术全景:这个插件到底用了哪些技术

你问的「顺便讲讲用到的所有技术」,这一章就是总账。
每一组我按同一个套路写:**这是什么 → 项目里用在哪 → 为什么用它 → 想学从哪入手**。

最后还有一张总表和一份「这个项目故意没用的技术」(对初学者挺重要,能帮你分清
「必须会」和「可以以后再会」)。

--------------------------------------------
## A. 语言与运行时层

**A1. JavaScript(ES2015~ES2020+ 语法)**
- 用在哪:全部代码。
- 关键语法:let/const、箭头函数、解构、展开、模板字符串、可选链 ?.、空值合并 ??、
  Promise / async-await、模块、Map/Set。
- 为什么:这些是「现代 JS 的日常语法」,不会就等于每行都在猜。
- 从哪学:01、02、03 章 + MDN 的语法索引。

**A2. Node.js 运行时**
- 用在哪:lib/index.js(宿主桥接)、deskpet.mjs(桌宠)、test/core.test.mjs(测试)。
- 用到的能力:文件读写、路径处理、子进程、环境变量、HTTP、压缩、定时器。
- 为什么:插件需要「离开浏览器」的能力 —— 碰文件、开进程、当服务器。
- 从哪学:05 章 + Node 官方文档的 fs / path / child_process / zlib。

**A3. ESM 与 CJS(两套模块系统)**
- 用在哪:引擎文件 .mjs(ESM)、浏览器半边 CJS 工厂、包 exports 表。
- 为什么:一个是现代标准,一个是历史兼容;混用不当会直接让插件加载失败(事故 B)。
- 从哪学:04 章。

**A4. JSON / 正则 / Buffer / 定时器 / AbortController**
- JSON:状态存盘(character.json、progress-*.json)、HTTP 请求体。
- 正则:清洗文件名、过滤括号里的动作描写、日期格式校验。
- Buffer / TypedArray:读二进制(压缩日志、PNG 角色卡)。
- 定时器:心跳(60s)、桌宠轮询(300ms)、备份镜像(60s)。
- AbortController:agent 钩子里判断这一轮是不是被取消了。
- 从哪学:02、03、05 章的对应小节。

## B. DSH 平台层(这个项目的"操作系统")

**B1. Cordis 插件框架**
- 用在哪:每个插件都长成 { name, inject, apply(ctx, config) }。
- 提供什么:插件加载、服务注册与查找、依赖注入、生命周期、事件钩子、隔离域、分组。
- 为什么:整个 DSH 就是一棵插件树;不懂它,你写的代码不知道该往哪儿放。
- 从哪学:06 章。

**B2. agent preset(会话级插件组合)**
- 用在哪:agent-presets/roleplay|friend|oc/agent.cordis.yml。
- 作用:一个会话用哪套插件、什么配置,全由这些 yml 决定。
- 为什么:同一份引擎代码,靠配置就能变成三种玩法(恋爱向/朋友向/OC 向)。
- 从哪学:06 章 + 项目里三份 yml 对照着读。

**B3. 会话与事件流(session / events / seq)**
- 用在哪:chatPoll 读 session.events;侧栏靠 seq 做增量。
- 作用:会话里发生的每件事(用户消息、助手消息、工具调用、轮次开始结束)都是一条事件,
  带一个递增的 seq。
- 为什么:它是「聊天记录」的唯一真相来源,也是排查问题的第一手证据(事故 A 就靠它)。
- 从哪学:03 章(增量轮询)+ 09 章(拿去当证据)。

**B4. agent 生命周期钩子(agent/pre-step、agent/turn-stopping)**
- 用在哪:roleplay-host.mjs 的注入逻辑(心跳消息注入、消息过滤)。
- 作用:在「这一轮要开始」「这一轮要结束」的时候插一脚。
- 为什么:这是插件影响模型输入输出的正式入口,也是**最容易写崩整轮对话**的地方。
- 从哪学:06 章的 6.6。

**B5. 工具注册(roleplay_xxx 这些工具)**
- 用在哪:roleplay-host.mjs 里注册的 12 个工具(记记忆、改关系、看桌面、开游戏…)。
- 作用:给模型一批「可以调用的函数」,让它能真的改状态,而不只是嘴上说。
- 为什么:这是「让 AI 真的做事」的关键机制。
- 从哪学:roleplay-host.mjs 的 tools.register 部分 + 06 章。

**B6. system prompt 分段注入**
- 用在哪:角色人设、扮演规则、记忆摘要、关系档位行为,都是以「段」的形式注入系统提示。
- 作用:按条件动态生成提示词(不同阶段、不同模式给不同的规则)。
- 为什么:这是控制模型行为最直接的手段,也是这个项目最核心的「玩法工程」。
- 从哪学:roleplay-host.mjs 里 systemPrompt.section 的用法。

**B7. 设置命名空间 + schema(schemastery)**
- 用在哪:lib/settings.js 注册 roleplay 命名空间的配置项。
- 作用:让插件在 DSH 的「设置 → 插件」里有一张配置卡片,字段带类型和默认值。
- 为什么:配置有 schema 就等于有校验,面板、文件、代码三处不会各说各话。
- 从哪学:lib/settings.js + 06 章。

**B8. 平台服务**
- agents:找会话、拿会话、按会话解析服务;
- fs:带沙箱的文件读写;
- subprocess:起子进程(桌宠窗口);
- webServer:挂自己的 HTTP 路由;
- timer:定时器;
- sandboxPolicy:权限策略(能不能写这个路径);
- attachments / skills:附件与技能目录。
- 从哪学:05、06 章,再对着 lib/index.js 看它们怎么被用。

**B9. UI 插槽(slot 系统)**
- 用在哪:lib/client.js 往输入区、消息尾部塞按钮和浮层。
- 作用:插件不改宿主 DOM,只往宿主预留的「洞」里注册组件。
- 为什么:宿主升级不会打断插件;插件也没机会搞坏宿主界面。
- 从哪学:07 章。

## C. 前端与浏览器层

**C1. 手写的 client bundle + 模块加载器**
- 用在哪:lib/client.js 开头的 window.__ModuleLoader__.load({ id, factory })。
- 作用:把「一个插件」注册进页面,由宿主注入 React 等公共依赖。
- 为什么:零构建、无版本漂移、改完刷新就是新的。
- 从哪学:07 章。

**C2. React(不写 JSX 的写法)**
- 用在哪:侧栏、对话栏、按钮、徽章。
- 用到的概念:组件就是函数、useState 驱动重画、useEffect 放副作用和清理、
  createElement(标签, 属性, 子节点)。
- 为什么:宿主页面就是 React 写的;顺着它写最省事。
- 从哪学:07 章 + useChat 那段代码精读。

**C3. fetch 与统一信封**
- 用在哪:rpc(ep, payload) 一个函数包打天下。
- 作用:POST JSON 到 /roleplay/<endpoint>,返回 { ok, value, error }。
- 为什么:两层 ok 把「通信成功」和「业务成功」分清楚,错误处理不打架。
- 从哪学:07 章 + lib/client.js 的 unwrap 注释。

**C4. DOM 与 CSS 注入**
- 用在哪:注入样式表、滚动消息到底部、读输入框内容。
- 用到的点:document.createElement / appendChild / removeChild、scrollTop/scrollHeight、
  class 命名前缀、主题变量、:has() 选择器。
- 从哪学:07 章 + MDN 的 DOM 部分。

**C5. 层叠与指针事件(z-index / pointer-events / 层叠上下文)**
- 用在哪:侧栏、浮层、按钮的显示层级。
- 为什么:这是浏览器最容易出「玄学」的地方 —— 事故 C 就是浮层把点击吃了。
- 从哪学:09 章事故 C + MDN 的 stacking context。

**C6. 轮询(polling)**
- 用在哪:对话侧栏每 1.5 秒拉一次新消息。
- 作用:用最简单的方式实现「准实时」。
- 为什么:比 WebSocket 简单,量小的时候完全够用(代价是有 1.5 秒延迟)。
- 从哪学:07 章的 useChat。

## D. 桌面与 Windows 互操作层(桌宠/便签)

**D1. PowerShell 5.1 脚本**
- 用在哪:pet/pet-window.ps1、pet/note-window.ps1。
- 作用:开窗口、画立绘、处理拖动/右键菜单、跟 Node 用 HTTP 通信。
- 为什么:Windows 上「不装任何东西就能开个透明窗口」的最短路径。
- 从哪学:这两个脚本本身(注释写得很细)+ 05 章的子进程部分。

**D2. WPF / XAML(在脚本里写界面)**
- 用在哪:窗口、菜单、气泡、便签贴纸。
- 用到的点:Window 属性(WindowStyle=None、AllowsTransparency、Topmost)、
  Canvas/Image/TextBlock、Storyboard 动画。
- 从哪学:pet/pet-window.ps1 的 XAML 片段。

**D3. System.Drawing 与图片处理**
- 用在哪:读取图片尺寸、把立绘缩放到合适大小、按 alpha(透明度)采样出「哪块能点」。
- 为什么:透明区域应该让点击穿透到下面的窗口,只能靠采样判断。
- 从哪学:pet/*.ps1 里的 Apply-Scale / alpha 采样函数。

**D4. Win32 API(通过 Add-Type 调)**
- 用在哪:设置窗口样式(WS_EX_TRANSPARENT 让点击穿透)、
  取窗口句柄、跟随鼠标穿透策略。
- 为什么:纯 WPF 做不到「点击穿透」这种系统级行为。
- 从哪学:pet/*.ps1 里的 Add-Type 声明。

**D5. 单实例与进程自检(Mutex + 版本文件)**
- 用在哪:防止桌宠/便签开出多个窗口;旧版本进程自动让位。
- 做法:窗口脚本用 Mutex 保证单实例;deskpet 写一个 window-version.txt,
  窗口每 10 秒比对版本,不一致就自己退出。
- 为什么:历史事故 —— 旧进程占着锁,新版本永远起不来。
- 从哪学:deskpet.mjs 的 writeWindowVersion + pet/*.ps1 的自检段。

**D6. 子进程与 stdio 收集**
- 用在哪:deskpet.mjs 用 subprocess.spawn 拉起窗口。
- 要点:参数数组、cwd、stdout/stderr 收集上限、退出回调。
- 从哪学:05 章。

**D7. 编码与 BOM**
- 用在哪:所有 .ps1 文件必须有 UTF-8 BOM;中文参数传递。
- 为什么:PowerShell 5.1 没 BOM 会按 ANSI 解,中文直接变乱码、脚本语法错。
- 从哪学:08 章的 8.5。

## E. 数据与持久化层

**E1. JSON 文件当数据库**
- 用在哪:character.json、progress-<角色>.json、mem-<角色>.json、cards.json、config.json…
- 为什么:零依赖、能人工看、能 git diff;单人规模完全够。
- 代价:没有事务、没有索引 —— 所以项目用「写前备份 + 单飞写入 + 读合并」来补。

**E2. 按角色分文件隔离**
- 用在哪:文件名里带角色 key(清洗过非法字符)。
- 为什么:换角色不影响别人的进度;删一个角色不影响其他人。

**E3. 分层备份与恢复**
- L1 写盘前 .bak:主存档写之前留一份;
- L2 每日快照:独立目录、保留最近 3 份;
- L3 用户级镜像:每 60 秒镜像到用户目录(跨工作区、耐删);
- L4 灾后回流:数据根缺文件就从最近镜像补回。
- 为什么:用户的角色数据是「不可再生资产」;这个项目真的丢过一次数据。
- 从哪学:lib/backup-core.mjs + lib/index.js 的 mirrorBackups。

**E4. 会话日志(JSONL + zstd)**
- 用在哪:排查事故时读 DSH 的会话日志。
- 做法:多帧 zstd 压缩的 JSONL;解压后一行一个事件,按 seq 排。
- 为什么:这是系统最完整的事实记录,事故 A 就是靠逐条读它破的。
- 从哪学:09 章事故 A + Node 的 zlib.zstdDecompressSync。

**E5. 二进制内嵌数据(PNG 角色卡)**
- 用在哪:把角色卡 JSON 写进 PNG 的 tEXt 块里(就像酒馆的角色卡那样)。
- 为什么:一张图就是一张卡,好传好存。
- 从哪学:lib/png-card.mjs。

**E6. 快照备份(robocopy)**
- 用在哪:改动数据目录之前先复制一份快照。
- 为什么:改坏了能整体回退 —— 这是所有数据操作前的「安全带」。

## F. 传输与协议层

**F1. HTTP 前缀路由**
- 用在哪:bridge 把 /roleplay/* 挂到 DSH 的 webServer 上。
- 要点:仅本机、仅 POST、白名单端点、请求体上限、统一 envelope。

**F2. 自定义 JSON 信封**
- 形状:{ ok, value?, error? }。
- 为什么:一端说一套话最省事;两层 ok 分清通信/业务。

**F3. 目标会话解析(按预设 id 找会话)**
- 用在哪:桌宠找到「哪个会话是角色扮演会话」;侧栏找到要连的会话。
- 做法:遍历根会话,读它的 agentPreset(会话头 + 事件里的 agent-preset/selected)。
- 为什么:插件是共享的,但状态要按会话分开。

## G. 工程质量层

**G1. 自研测试 harness + 门禁**
- T0 语法门、T0b PowerShell BOM 门、T1~T42 行为测试。
- 为什么:零依赖、跑得快、失败信息自己写的最好懂。

**G2. 假 ctx / 黑盒桥接测试**
- 做法:造一个最小 ctx + 假 fs + 假服务,直接把插件 apply 起来调;
  桥接测试连 webServer 都 mock 掉,直接调路由 handler。
- 为什么:不启动真 DSH 也能测集成。

**G3. 版本与物化(materialize)**
- 机制:包内预设复制到用户目录 + 写 .rp-version 标记;版本一致就跳过。
- 坑:改了文件忘升版本号 → 永远不复制 → 用户加载旧代码(项目真踩过)。
- 从哪学:lib/index.js 的 materializePresets。

**G4. 缓存版本号**
- 形态:./lib/chat-core.mjs?v=2、'./roleplay-host.mjs?gen=33'。
- 作用:给模块换一个「身份」以绕过缓存。

**G5. 包管理与发布**
- npm/pnpm:插件以包形式安装进 DSH 的 profile;
- package.json 的 exports:对外暴露哪些入口;
- 本地源安装:file:D:/dsh/repo/dsh-roleplay-plugin;
- git/GitHub:小步提交、提交信息写清「现象→根因→修法」。

**G6. 日志与诊断**
- 统一前缀(如 [deskpet]、[roleplay])便于 grep;
- 错误一定带堆栈;
- 关键路径埋「我在干什么」的日志(startPet dir=... script=... port=...)。

## H. 方法论与纪律(不是技术,但比技术重要)

1. **证据优先**:先翻日志/事件流/元素栈,再改代码;
2. **二分定位**:注释掉一半,问题还在就换另一半;
3. **边界兜底**:每个入口 try/catch,记堆栈,返回结构合法的兜底值;
4. **契约意识**:数据结构就是接口,少一个字段能炸一条链;
5. **层级判断**:会话级 vs 整机级、私有域 vs 公共域,想清楚再放;
6. **数据不可动**:用户数据只读;要动先快照;
7. **改完实测**:没验证过的修复等于没修;
8. **小步提交**:一次一件事,提交信息写清楚。

## 这个项目**故意没用**的技术(别被吓到)

- **TypeScript**:因为宿主运行时要直接吃裸 JS/ESM(不过你学它绝对值得);
- **打包器(vite/webpack/rollup)**:浏览器半边是手写的,零构建更省心;
- **React JSX**:用 createElement 手写,省掉编译这一步;
- **数据库 / ORM**:JSON 文件 + 备份就够;
- **Docker / 容器**:插件跑在用户的 DSH 里,不需要;
- **测试框架(Jest/Vitest)**:自研 200 行 harness 够用;
- **WebSocket**:轮询足够,少一层复杂度;
- **状态管理库(Redux 之类)**:组件自己 useState 就够。

看到没?**一个真能用的插件,并不需要把所有时髦工具都用上。**
选最少的工具解决问题,是更容易维护的路子 —— 这也是这个项目最想教给你的工程观。

## 学完这一章,你可以做的一件事

把这个总表打印出来(或者存成自己的笔记),每学完一项就在后面打个勾,
并且写一句话:「它解决什么问题,我在项目里见过它在哪」。

等你把 30 多项都打过勾,你就不是「JS 初学者」了 ——
你是一个能独立维护这类插件工程的开发者。
