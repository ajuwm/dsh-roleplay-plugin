# 01 · 心智模型:先把脑子里的 C++ 换掉一半

这章不讲语法,只讲一件事:**你从 C++ 带过来的哪些直觉,在 JS 里是错的。**
后面所有章节都建立在这章的结论上。

--------------------------------------------
## 1.1 类型是运行时才有的东西

C++ 里类型是编译期的事实:变量有类型、函数有签名,类型不对根本编译不过。
JS 反过来 —— **类型跟着值走,而且运行时才知道**:

    let a = 1
    a = 'hello'        // 同一个变量,现在是字符串,没人拦你
    a = { x: 1 }       // 又变成对象了,还是没人拦你

看项目里真实的一段(lib/client.js,处理桥接返回值的工具函数):

    var unwrap = function (result) {
      if (result && result.value !== undefined && result.value !== null) return result.value
      if (result && result.error && result.error.message) return { ok: false, message: result.error.message }
      return null
    }

这段要是在 C++ 里根本不用写 —— 编译器保证 result 有 value。
在 JS 里,**每次跨边界取数据都得自己防一手**,因为你永远不知道对面塞了个啥进来。

【C++ 老习惯会坑你】JS 没有函数重载、没有模板、没有编译期检查。
TypeScript 能把一部分检查找回来,但这个项目故意没用 TS —— 因为 DSH 运行时要直接吃
裸的 JS/ESM 文件,中间不想插一层编译。

看看 JS 有哪些类型,顺便对照一下:

| JS | 意思 | 相当于 C++ 的 |
|---|---|---|
| number | 唯一的数字类型,IEEE754 双精度 | double(没有 int/float 之分) |
| bigint | 任意精度整数,写作 1n | 大整数库 |
| string | 不可变的 UTF-16 序列 | std::u16string |
| boolean | true / false | bool |
| undefined | 「压根没赋过值」 | 无对应(像未初始化的内存) |
| null | 「我明确置空」 | nullptr |
| object | 一切引用型:数组、函数、实例… | 各种指针 |
| symbol | 独一无二的键,元编程用 | 无对应 |
| function | 函数也是对象,能当参数传 | std::function,但自由得多 |

**undefined 和 null 的区别**是新手第一个坑:undefined 是系统给的(没赋值、没这个属性),
null 是人给的(我主动置空)。项目里两个都要防:

    const decision = await next()
    if (decision === undefined || decision === null) { ... }

--------------------------------------------
## 1.2 值复制还是引用复制,规则很简单

C++ 里按值还是按引用你自己说了算(还有 const 引用这种中间态)。
JS 的规则粗暴但好记:

- **基本类型**(number / string / boolean / null / undefined / bigint / symbol)按值复制;
- **对象、数组、函数**复制的是「指向同一个堆对象的把手」。

    let a = { n: 1 }
    let b = a          // 不是拷贝!a 和 b 指的是同一个对象
    b.n = 2
    console.log(a.n)   // 2

真心想拷贝:浅拷贝用 { ...obj },深拷贝用 JSON.parse(JSON.stringify(obj))
(只能处理 JSON 装得下的东西)或者现代 Node 自带的 structuredClone。

【C++ 老习惯会坑你】JS 的 const 不是 const 引用。它只保证「这个名字不再指向别的对象」,
**对象里面的东西照样能改**:

    const s = { level: 1 }
    s.level = 99       // 完全合法

--------------------------------------------
## 1.3 比较:永远用 ===

- === :类型和值都得一样(请只用这个)
- == :会偷偷帮你转类型,规则怪到能当笑话看([] == false 居然是真的)

比较两个对象时,=== 比的是「是不是同一个对象」,不是内容:

    { a: 1 } === { a: 1 }   // false —— 两个不同的对象

想比内容就自己写字段比较,项目里就是这么干的:

    const same = x.id === y.id && x.name === y.name

--------------------------------------------
## 1.4 真假值:空数组也是「真」

if 里不一定非得是布尔值,JS 会自动转。**只有这几个是假**:
false、0、-0、0n、空字符串 ''、null、undefined、NaN。其它一律为真 —— **包括空数组和空对象**。

【C++ 老习惯会坑你】空数组是「真」!所以千万别写 if (arr) 判断非空,
得写 if (arr.length) 。项目里的写法:

    if (!Array.isArray(events) || events.length === 0) return { messages: out, lastSeq: ... }

顺手记两个现代语法,能少写一堆判断:

    a ?? b    // 空值合并:只有 a 是 null/undefined 才用 b(0 和空字符串会被保留,这点跟 || 不一样)
    a?.b      // 可选链:a 是空就直接给 undefined,不会报「读不到属性」

--------------------------------------------
## 1.5 函数是「一等公民」,闭包是日常工具

C++ 有 lambda,但 JS 把「函数就是普普通通一个对象」推到了极致:
能塞进变量、能当参数、能当返回值、还能挂属性。而**闭包**(函数记住自己出生时的环境)
在这儿不是高级技巧,是每天都要用的东西。

项目里最大的一个闭包就是整个扮演引擎(roleplay-host.mjs):

    export function apply(ctx, config) {
      const STYLE = (config && config.style) || 'love'
      const REL_ROOT = (config && config.dataRoot) || '.roleplay'
      const fs = ctx.fs

      async function saveState() {                     // 这个函数「记得」上面的 fs、REL_ROOT
        if (!fs) return
        await enqueueWrite(REL_ROOT + '/character.json', async () => { ... })
      }

      ctx.provide('roleplay', {                        // 对外提供的接口,也是闭包
        getState: async () => { ... },
        chatSend: async (args) => { ... },
      })
    }

你可以这么理解:apply 一执行,就造了一个「小世界」——里面住着 state、memory、
pendingHeartbeats 这些变量,外面只能通过它交出来的那几个函数跟它打交道。
这既是封装,也是**内存泄漏的高发区**(闭包不释放,它抓着的东西都不释放)。

【C++ 老习惯会坑你】JS 闭包抓的是**变量本身**(还能继续读改),不是抓一份快照。异步代码里
这会让「你看到的数据」比你以为的更新:

    let count = 0
    const fns = []
    for (var i = 0; i < 3; i++) fns.push(function () { return i })
    console.log(fns.map(f => f()))    // [3, 3, 3] —— 因为 var 只有一个 i
    // 把 var 换成 let,就变成 [0, 1, 2]

--------------------------------------------
## 1.6 this:看的不是「我在哪个类里」,而是「你怎么调我」

C++ 的 this 编译期就定死了。JS 的 this 完全看**调用现场**:

    const obj = { name: 'a', hi: function () { return this.name } }
    obj.hi()             // 'a' —— 当成方法调,this 就是 obj
    const f = obj.hi
    f()                  // 报错/undefined —— 光秃秃地调,this 没了

项目里的应对办法很干脆:**全用箭头函数**。箭头函数没有自己的 this,
写起来就不用操心这个坑了:

    const rpc = (ep, payload) => fetch('/roleplay/' + ep, { ... })

--------------------------------------------
## 1.7 原型:对象之间「串门」,不是类继承

JS 的继承不是类的继承,而是**对象和对象用原型链挂着**:
找属性时一层层往上找,直到找不着。class 只是这套东西的漂亮外衣。

【C++ 老习惯会坑你】没有 private/protected 的硬保证,没有纯虚函数/接口
(靠「鸭子类型」:会游泳的就是鸭子),也没有虚析构那套问题 —— 因为压根没有析构。

这个项目几乎不用 class,而是「工厂函数返回一个对象」:

    ctx.provide('roleplay', {
      getState: async (args) => { ... },
      peek: async () => { ... },
    })

JS 圈管这叫「组合优于继承」,也是 Cordis 生态的默认风格。

--------------------------------------------
## 1.8 内存交给 GC,但「句柄」得自己收

- 没有 new/delete、没有析构、没有悬垂指针(但有一堆空引用);
- 循环引用也不怕(标记清除算法能处理);
- 真正的坑是**忘了松手**:闭包、全局缓存、事件监听器、定时器、子进程。

长命的容器一定要自己设上限,项目里到处是这种「截断」:

    if (stageEvents.length > 30) stageEvents.length = 30
    if (state.recentActs.length > 8) state.recentActs.splice(0, state.recentActs.length - 8)

【C++ 老习惯会坑你】JS 里定时器、子进程、文件句柄**不会被 GC 顺手收掉**,
必须自己 clearInterval / terminate / 关掉。这个项目在桌宠模块上就栽过跟头:
清理钩子写在了不支持的上下文里,结果整个插件加载失败(06 和 09 章细讲)。

--------------------------------------------
## 1.9 单线程 + 事件循环(细节在 03 章)

JS 只有一条主线程跑你的代码;所有 I/O(文件、网络、子进程)都是异步的,
干完了把回调排进队列,事件循环再回头执行。

好处:**你的代码永远不会被另一个线程同时改**(没有数据竞争,不用锁)。
代价:**绝对不能写阻塞循环** —— 一个 while 死等,整个进程就僵住了。
顺序靠 await 保证,不是靠锁。

【C++ 老习惯会坑你】JS 说「同时干两件事」,通常指「一口气发起两个异步操作」,
不是「开两个线程」。真要多核算力得用 worker_threads —— 这个项目用不上。

--------------------------------------------
## 这一章记住三件事

1. 类型是运行时的事 → 数据进出边界时自己先防一手;
2. 比较用 ===,对象比的是「同一个」;判断非空用 length,别用真假;
3. 函数 + 闭包 = JS 的日常武器;资源(定时器/子进程)要自己收尾。
