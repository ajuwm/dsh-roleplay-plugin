# 02 · 语法对照:一个点一个点对着 C++ 讲

每节的套路都一样:先看 C++ 怎么写,再看 JS 怎么写,然后翻到项目里找个真实例子,
最后踩一下坑。

--------------------------------------------
## 2.1 变量:const、let,还有别碰的 var

    const x = 1     // 不能重新赋值(但对象内容随便改)
    let   y = 2     // 可以重新赋值,块级作用域
    var   z = 3     // 老古董:函数级作用域 + 变量提升,新代码别用

项目里到处是这种「先防一手再取值」的写法:

    export const name = 'roleplay-host'
    export const inject = ['agents', 'fs', 'systemPrompt', 'timer', 'sandboxPolicy', ...]

    export function apply(ctx, config) {
      const STYLE = (config && config.style) || 'love'
      const REL_ROOT = (config && config.dataRoot && typeof config.dataRoot === 'string')
        ? config.dataRoot
        : '.roleplay'

第二段就是典型:配置可能没传、可能传了但不是字符串,所以先 typeof 再决定用不用。

--------------------------------------------
## 2.2 字符串

    const a = 'single'
    const b = "double"                     // 单双引号一样
    const c = `${a} 和 ${b},长度 ${a.length}`   // 模板串:能换行、能插值
    const d = 'a' + 'b'                    // 拼接也行

项目里的模板串(lib/index.js 的报错信息):

    message: `unknown endpoint ${endpoint}`

常用方法(全都会返回新串,字符串是不可变的):

    s.trim()  s.slice(0, 40)  s.split(',')  s.startsWith('rp-')  s.includes('x')
    s.replace(/[\\/:*?"<>|]/g, '_')         // 正则替换
    String(x)  Number(s)  parseInt(s, 10)

看一个真实的「清洗文件名」函数(roleplay-host.mjs),我把它拆开念一遍:

    function charKeyFor(name) {
      const n = String(name || '').trim()        // 可能是 undefined → 先转字符串再 trim
      if (!n) return '_default'                  // 空名字兜底
      return n.replace(/[\\/:*?"<>|]/g, '_')      // Windows 文件名的非法字符换成下划线
              .replace(/\\s+/g, '_')              // 空白压成一个下划线
              .slice(0, 40) || '_default'        // 太长就截断;万一是空的再兜底
    }

七行代码,四个防御点 —— 这就是 JS 的日常。

## 2.3 数字

只有一种数字类型,整数小数共用。注意这几条:

    0.1 + 0.2 === 0.3     // false(浮点误差,C++ 也一样)
    2 ** 10               // 1024
    '5' + 1               // '51'  ← 字符串拼接!
    '5' - 1               // 4     ← 减号没有字符串版本,所以变成了数字运算

最后两条是新手头号 bug。项目里凡是外面传进来的数字,一律显式转换:

    const since = Number(args && args.since) || 0
    const limit = Number(args && args.limit) > 0 ? Number(args && args.limit) : 60

（Number(undefined) 是 NaN,NaN || 0 就得到 0 —— 这是最省事的「兜底 0」写法。）

--------------------------------------------
## 2.4 数组:比 vector 多了好多「函数式」工具

    const xs = [1, 2, 3]
    xs.push(4)                 // 尾部加
    xs.map(f)                  // 转换 → 新数组
    xs.filter(f)               // 过滤 → 新数组
    xs.find(f)                 // 找第一个满足的(找不到给 undefined)
    xs.some(f) / xs.every(f)   // 有没有 / 是不是全都
    xs.reduce(f, init)         // 归约
    xs.slice(a, b)             // 切片(不改原数组)
    xs.splice(a, n)            // 原地删
    xs.join(', ')

【和 C++ 对照】map/filter ≈ transform + copy_if(但 JS 直接返回新数组);
find ≈ find_if;reduce ≈ accumulate。数组是动态的,没有容量概念。

看项目里性能敏感的一段(chat-core.mjs 的「从尾部倒着扫」):

    for (let i = events.length - 1; i >= 0; i--) {
      const ev = events[i]
      if (!ev || typeof ev.seq !== 'number') continue
      if (ev.seq <= since) break            // 早停:事件是按 seq 递增的,扫到旧的就不必再扫
      const m = extractMessage(ev)
      if (m) got.push({ seq: ev.seq, ...m })
      if (got.length >= limit * 2) break
    }

为什么要倒着扫?因为聊天侧栏每 1.5 秒来问一次「有没有新消息」,
如果每次都从头扫几万条事件,长会话会越来越卡。倒着扫 + 撞到旧序号就停,
复杂度从「跟全部历史成正比」变成「跟新增消息成正比」。

【C++ 老习惯会坑你】JS 数组越界不报错,给你 undefined;
length 是个可写属性(改小它会真的截断数组,项目里就靠这招限长度)。

## 2.5 对象:键是字符串,写法一堆

    const o = { a: 1, 'b-c': 2, [dynKey]: 3 }   // 键可以用表达式
    o.a          // 1
    o['b-c']     // 2 —— 有特殊字符就得用方括号
    o.missing    // undefined,不报错
    Object.keys(o) / Object.values(o) / Object.entries(o)

解构(最常用的糖):

    const { ok, value, error } = result      // 从对象里抠字段
    const [first, ...rest] = arr             // 数组解构 + 剩下的全给 rest
    const { a = 1 } = cfg                    // 默认值
    const { x: renamed } = obj               // 改名

展开:

    const merged = { ...defaults, ...patch } // 后面的覆盖前面的
    const copy = [...arr]                    // 复制数组

项目实例(改一个字段但不动原对象):

    state.game = { ...next, waitWaiting: !next.over }

读作:「把 next 的字段全拷过来,再把 waitWaiting 换成新值」。

## 2.6 函数:三种写法都要认识

    function add(a, b) { return a + b }             // 声明式(会被「提升」,写在后面也能调)
    const add2 = function (a, b) { return a + b }   // 表达式
    const add3 = (a, b) => a + b                    // 箭头函数(单表达式可省 return)
    const f = (a = 1, ...rest) => ({ a, rest })     // 默认参数 + 剩余参数

这个项目三种都有:
- 引擎文件(function 和箭头混着用);
- 浏览器那半边(lib/client.js)故意写成最早的 var + function(){} 风格 ——
  因为它是手写的 bundle,要满足 DSH 模块加载器给的 CJS 工厂约定;
- 测试文件里箭头函数居多。

测试里的真实片段:

    const ok = (cond, label) => { ... }
    const boot = async (style = 'love', seedChar = null, dataRoot = '.roleplay') => { ... }

## 2.7 控制流

    if / else / for / while / switch / try-catch-finally / throw
    for (const x of arr) {}        // 遍历值
    for (const k in obj) {}        // 遍历键(对象用;数组别用,会拿到下标字符串和原型上的键)

项目里更喜欢「一串 if 提前 return」,比如桥接的分发(lib/index.js):

    if (endpoint === 'get-state') return { ok: true, value: await face.getState({ sessionId }) }
    if (endpoint === 'start')     return { ok: true, value: await face.start({ sessionId }) }
    ...
    return { ok: false, error: { code: 'bad-endpoint', message: 'unknown endpoint' } }

比 switch 顺手:不用写 break,也不会不小心贯穿。

## 2.8 类与原型(认识就行)

    class Point {
      constructor(x, y) { this.x = x; this.y = y }
      get norm() { return Math.hypot(this.x, this.y) }   // getter
      static origin() { return new Point(0, 0) }
    }
    class Point3 extends Point {
      constructor(x, y, z) { super(x, y); this.z = z }
    }

这个项目基本不用 class,数据模型是「普通对象 + 纯函数」。
比如 lib/relation-core.mjs 里全是这种:

    export function applyDelta(rel, delta, opts) { ... return { ...rel, favor: ... } }

好处很实在:纯函数好测试(给什么得什么,没有副作用),也好并发(不会互相改)。

【C++ 老习惯会坑你】别用 instanceof 判断业务类型(跨模块、跨环境会失灵),
项目里一律看字段 —— 比如判断消息是不是插件注入的,看的是 source.kind 和 id 前缀。

## 2.9 错误处理

    try { risky() }
    catch (e) { console.error(e && e.stack ? e.stack : e) }
    finally { cleanup() }

JS 里什么都可能被 throw —— 字符串、对象、甚至 undefined,所以 catch 里也要防:

    catch (e) { console.error('[roleplay] agent/pre-step failed:', e && e.stack ? e.stack : e) }

项目里的错误处理有三条铁律(08 章会展开):
1. **边界处一律 try/catch**:HTTP 路由、事件钩子、定时任务,绝不让一个异常炸掉整条链;
2. catch 了要**记堆栈**,不是默默吞掉;
3. 宁可返回一个「安全的兜底值」,也别把 undefined 往外传(传出去别人一取属性就崩)。

## 2.10 内建对象速查

    JSON.parse / JSON.stringify(v, null, 2)
    Array.isArray(x) / Object.entries(o) / Object.assign({}, o)
    Math.* / Date.now() / new Date()
    setTimeout / clearTimeout / setInterval / clearInterval
    Map / Set(当字典和集合用,比对象/数组更专业)
    structuredClone(v)

【C++ 老习惯会坑你】JSON.stringify 会丢掉函数和 undefined 字段,遇到循环引用直接抛错。
所以「存盘的状态」只能是纯数据 —— 项目里的 state.json 就是这么来的:

    await fs.writeText(target, JSON.stringify(stateForSave(), null, 2), undefined, undefined, policyFor())

第二个参数 null 是「不做替换」,第三个 2 是缩进两格(方便人肉看 diff)。

## 这一章记住三件事

1. const/let 是常态,var 当它不存在;
2. 数字从外部进来先 Number(),字符串拼接的 + 是经典陷阱;
3. 对象/数组都是引用,想要副本得自己展开或深拷贝。
