# 07 · 浏览器侧:界面、fetch、React,以及插槽系统

这个项目最神奇的地方在于:它的界面不是一个网站,而是**一段被 DSH 加载进去的插件代码**,
直接长在 DSH 的聊天页面上 —— 输入框上方多了两个按钮,侧边多了两栏。

这一章讲它怎么做到的,以及你会用到哪些浏览器侧的技术。

--------------------------------------------
## 7.1 它是被「装进」页面的,不是自己开的页面

看 lib/client.js 的头两行,信息量很大:

    window.__ModuleLoader__.load({
      id: '@ajuwm/dsh-roleplay-plugin',
      factory: function (require) {
        var React = require('react')
        ...
      },
    })

逐点解释:

- 页面里有个全局的模块加载器(DSH 自己的);你把「模块 id + 工厂函数」注册进去;
- id 必须和配置里的行 id 一致(否则加载器找不到对应关系);
- React 这类「公共依赖」不是你自己装的,而是**由加载器注入给你**(所以是 require('react'),
  而不是 import React from 'react');
- 工厂函数返回的就是一个 Cordis 插件({ name, inject, apply }),和 Node 那边长得一模一样。

**为什么不打包?** 因为这样最省事也最稳:没有构建步骤、没有版本漂移,
代码就是浏览器直接执行的那份,改完刷新页面就是新的。

【C++ 老习惯会坑你】浏览器里的模块加载不是靠文件系统,而是靠「谁先注册」。
所以 id 拼错、依赖没声明,都表现为「静默不生效」,而不是编译错误。

## 7.2 跟后台说话:一个 20 行的 RPC 封装

桥接在 Node 那侧挂了 /roleplay/* 的 HTTP 路由,浏览器这边就一个 fetch 封装:

    var rpc = function (ep, payload) {
      return fetch('/roleplay/' + ep, {
        method: 'POST',
        headers: { 'content-type': 'application/json' },
        body: JSON.stringify(payload || {}),
      }).then(function (r) {
        return r.json().catch(function () {
          return { ok: false, error: { message: 'HTTP ' + r.status } }
        })
      })
    }

注意最后那个 .catch:即使服务器返回的不是 JSON(比如 502 的 HTML 错误页),
也不能让整个调用链崩掉,而是造一个统一形状的错误对象出来。

紧接着还有一层解包:

    var unwrap = function (result) {
      if (result && result.value !== undefined && result.value !== null) return result.value
      if (result && result.error && result.error.message) return { ok: false, message: result.error.message }
      return null
    }

它存在的理由写在注释里,而且是踩过坑的:

    ⚠ 必须兼容「业务失败」:桥接对失败会返回
      { ok:false, value:{ ok:false, message:'她刚吃过东西,等一会儿再喂吧。' } }
    老代码一律写成 result.ok && result.value → 只认 HTTP 层 ok=true,
    于是引擎给的真实原因(冷却中/金币不足…)全被替换成笼统的「操作失败」。

**这就是「统一信封」的价值**:外层 ok 表示「通信成功」,内层 ok 表示「业务成功」,
两者必须分开处理。设计接口时把这两层分清楚,能省掉未来无数的调试。

## 7.3 React:不用框架写法也要懂的心智

这个项目的界面代码是手写的 React.createElement 调用(不是 JSX),所以你能看清 React 到底在干嘛:

    var ChatPanel = function (props) {
      var targetsState = React.useState(null)      // 一个状态:目标会话列表
      var targets = targetsState[0]
      var setTargets = targetsState[1]
      ...

      return React.createElement('div', { className: 'rp-chat' },
        React.createElement('div', { className: 'rp-chat-head' }, ...),
        msgs.map(function (m) {
          return React.createElement('div', { key: m.id || m.seq, className: cls }, m.text)
        }))
    }

两个核心概念,记住就够用了:

**1) state:数据变了,界面自己重画。**

    var s = React.useState(0)      // s[0] 是当前值,s[1] 是修改函数
    var n = s[0]
    var setN = s[1]
    setN(n + 1)                    // 触发重画

**2) 组件就是函数:输入 props,输出「界面长什么样」。**
React 负责把它变成真实的 DOM。

而 useEffect 是「做副作用」的地方 —— 定时器、请求订阅、事件监听,都在这儿:

    React.useEffect(function () {
      aliveBox.v = true
      sinceRef.v = 0
      msgsBox.v = []
      setMsgs([])
      if (!targetId) return function () { aliveBox.v = false }
      rpc('chat-history', { target: targetId }).then(function (result) { ... })
      var id = window.setInterval(function () {
        rpc('chat-poll', { target: targetId, since: sinceRef.v }).then(applyPoll).catch(function () {})
      }, 1500)
      return function () { aliveBox.v = false; window.clearInterval(id) }   // 清理函数
    }, [targetId])                  // 依赖数组:targetId 变了就重新执行

这段是**最值得精读的一段界面代码**,它把好几件事揉在一起:

- **清理函数**:effect 返回的那个函数会在组件卸载(或依赖变化)时执行 —— 定时器必须在这里清;
- **依赖数组 [targetId]**:指定「什么时候重跑」,空数组 = 只跑一次;
- **轮询游标 sinceRef**:每 1.5 秒问一次「比上次序号大的消息」,而不是每次拉全部;
- **aliveBox 这个小技巧**:异步回来时组件可能已经卸载了,用它当「还活着吗」的标记,
  避免往已经消失的界面里塞数据(React 会警告)。

【C++ 老习惯会坑你】JS 的闭包 + React 的重渲染,会产生「你已经捕获了旧值」的问题
(经典的 stale closure)。项目里的解法是用一个对象当小盒子(msgsBox.v、sinceRef.v),
每次读写都从小盒子里拿,避开捕获快照。

## 7.4 样式:一段字符串直接塞进页面

项目没用什么 CSS 框架,直接把一大段样式拼成字符串,注入到 head:

    var style = document.createElement('style')
    style.textContent = [ '.rp-sb { ... }', '.rp-dock-btn { ... }', ... ].join('\n')
    document.head.appendChild(style)
    ctx.effect(function () {
      return function () { if (style.parentNode) style.parentNode.removeChild(style) }
    })

三个点:

- 类名统一加前缀(rp-),避免和宿主页面的样式打架;
- 注入完记得挂一个清理(插件卸载时把这段样式摘掉)—— 这就是 ctx.effect 的用法;
- 主题适配用 body 上的属性选择器(比如 body:not([data-ds-dark-theme]) 里换一套浅色变量)。

【本项目踩过的坑】样式里的 z-index 不是随便写的:输入框区域的 z-index 比弹窗蒙层还高的话,
输入框就会浮到「设置」弹窗上面(用户看到的怪现象);而宠物插件的浮层又可能盖住按钮,
把点击吃掉。**层叠上下文 + 指针事件**是浏览器侧最容易出玄学问题的地方,
09 章会完整讲一次。

## 7.5 插槽系统:不抢别人的地盘,只往预留的洞里塞东西

DSH 的界面是宿主写的,插件不能直接改它的 DOM。那按钮是怎么加到输入框上方的?
靠**插槽(slot)**:

    slots.inject('conversation.input.dock', function () {
      return slots.register(
        { name: 'conversation.input.dock', id: 'roleplay-entry', order: 100, label: '角色扮演' },
        function (props) { ... return React.createElement('button', ...) }
      )
    })

    slots.inject('conversation.input.overlay', function () {
      return slots.register(
        { name: 'conversation.input.overlay', id: 'roleplay-sidebar', order: 10, label: '角色扮演侧栏' },
        function (props) { ... }
      )
    })

读法:

- **inject(插槽名, 注册逻辑)**:「等宿主声明了这个插槽,再把我这段注册进去」;
- **register(规格, 组件)**:规格里 id 唯一、order 决定排第几、label 给调试看;
- 组件拿到的 props 里通常有 sessionId(当前会话),你用不到时可以忽略。

好处:宿主改版了,插槽协议还在,插件就还能用;你也不会有机会把宿主的界面搞坏。
这个项目用到的几个插槽:

| 插槽 | 位置 | 这个项目往里放了什么 |
|---|---|---|
| conversation.input.dock | 输入框上方一排按钮 | 🎭 角色扮演、💬 对话 |
| conversation.input.overlay | 输入区浮层 | 右侧角色侧栏、对话侧栏 |
| conversation.chat.turnTail | 每条消息尾部 | 🎭 角色名徽章 |

## 7.6 界面代码的几条纪律(项目里验证过的)

1. **所有网络调用都要 .catch** —— 断网、服务没起来时,界面不能白屏;
2. **轮询要有游标**(since),别每次全量拉;
3. **异步回调里先检查「我还活着吗」**,再 setState;
4. **别在渲染函数里发请求**(渲染会被调用很多次)—— 要用 useEffect;
5. **清理函数不是可选项**:定时器、监听器、注入的样式,全都要能收回;
6. **类名加前缀**,别和宿主或其他插件的样式撞车。

## 这一章记住三件事

1. 浏览器半边是「注册进加载器的插件」,id 和依赖都要按约定来;
2. 跟后台说话走统一信封(外层通信 ok / 内层业务 ok),请求一律 .catch;
3. React 就三件事:state 驱动重画、useEffect 放副作用、清理函数收尾;
   界面往宿主的插槽里塞,别去改宿主 DOM。
