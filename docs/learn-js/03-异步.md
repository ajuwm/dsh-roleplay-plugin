# 03 · 异步:从 C++ 过来最需要重新学的一章

说句实话:语法部分你花两天就能适应,真正会让你写出 bug 的,是异步。

好消息是:JS 的异步比多线程简单 —— 没有锁、没有竞态、没有内存序。
坏消息是:它换了一套完全不同的思维方式,你得先把「线程」这个词放下。

--------------------------------------------
## 3.1 单线程为什么不会卡死

想象一家只有一个服务员的餐厅:他不会站在厨房等菜做好,而是把单子递进去,
转身招呼别人;菜好了厨房按铃,他再回来端走。

JS 主线程就是这个服务员:

- 你的代码**永远在一条线上跑**,不会两个函数同时执行;
- 遇到 I/O(读文件、发请求、等子进程)时不是「等」,而是**把任务交出去 + 留个回调**;
- I/O 干完了,回调被排进队列,主线程一空就去取下一个执行。

这个循环叫**事件循环**(event loop)。由此得两条铁律:

1. **别写阻塞循环**。while (true) {} 会让服务员原地转圈,所有客人(包括界面)一起卡死。
2. **顺序靠 await**,不是靠加锁 —— 因为压根没别人跟你抢。

【C++ 老习惯会坑你】在 C++ 里「等 5 毫秒」你会 sleep_for。
在 JS 里连 sleep 都得是异步的:await new Promise(r => setTimeout(r, 5))。
写个同步死循环当 sleep,整个 DSH 都会僵住。

--------------------------------------------
## 3.2 从回调地狱到 async/await

远古写法叫回调地狱:

    readFile(a, (err, dataA) => {
      readFile(b, (err, dataB) => {
        writeFile(c, dataA + dataB, (err) => { ... })     // 再嵌两层就没法看了
      })
    })

后来有了 **Promise**:一个「未来会有结果」的占位物,三种状态 ——
pending(还没好)、fulfilled(成功)、rejected(失败);只能变一次,变完就定死。

    doSomething()
      .then(result => console.log(result))
      .catch(err => console.error(err))
      .finally(() => cleanup())

再后来有了 **async/await**,写起来几乎跟同步代码一样,但语义仍然是异步。

    async function run() {
      const a = await readFile(a)      // 在这儿等,但线程没闲着
      const b = await readFile(b)
      await writeFile(c, a + b)
    }

**关键理解**:await 不是「阻塞线程」,而是「把这个函数暂停在这儿、让出线程,
等 Promise 有结果了再回来接着跑」。函数内部看着是顺序的,外面该转的还在转。

项目里一条真实链路(侧栏发一条消息),你顺着读一遍就懂了:

    浏览器(lib/client.js)
      rpc('chat-send', { target, text })        → fetch POST /roleplay/chat-send
    DSH 主进程(lib/index.js)
      dispatch('chat-send', payload)            → 找到那个会话的 roleplay 服务
      await targetFace.chatSend({ sessionId, text })
    扮演引擎(roleplay-host.mjs)
      chatSend: async (args) => {
        await ensureLoaded()
        agent.send(message, 'next-turn', true)
        return { ok: true }
      }
    之后 DSH 跑一轮 agent、模型回话,浏览器那边再靠 chat-poll 每 1.5 秒把新消息取回来

全程没有任何一处「等」到卡住 —— 都在让出、等待、回来接着干。

## 3.3 并发:想同时做几件事就用 Promise.all

顺序 await 是一条条来;要并发就把几个 Promise 一起交出去:

    const [a, b] = await Promise.all([fetchA(), fetchB()])   // 一起跑,都好了才继续
    await Promise.allSettled([x(), y()])                     // 一起跑,不管成败,等全部结束
    const first = await Promise.race([fast(), slow()])       // 谁先回来用谁

项目里到处是「一个失败不影响别人」的写法(lib/index.js 的备份镜像),外层一个 try/catch,
里面每一步都单独兜住。

【C++ 老习惯会坑你】这个坑极其常见:

    // 错的:forEach 里的 await 不会等
    arr.forEach(async (item) => { await doSomething(item) })
    console.log('这行会在所有 doSomething 之前就跑')

    // 对的:要顺序用 for...of,要并发用 Promise.all + map
    for (const item of arr) await doSomething(item)
    await Promise.all(arr.map(item => doSomething(item)))

项目里所有「等完再往下」的循环,用的都是 for...of + await。

--------------------------------------------
## 3.4 错误:await 也要 try/catch

await 一个失败的 Promise 会当场抛异常 —— 所以它和同步代码一样能被 try/catch 抓住:

    try {
      const value = await targetFace.chatSend({ sessionId: sid, text: payload.text })
      return { ok: !!value.ok, value }
    } catch (error) {
      return { ok: false, error: { code: 'handler-error', message: String(error && error.message || error) } }
    }

只写 .then() 不写 .catch():失败会变成一条「未处理的 Promise 拒绝」警告,
调用方永远等不到结果 —— 新手最常见的异步坑。

项目里的原则很简单:**边界处一律兜住**。HTTP 路由、agent 钩子、定时任务,
都是「错了就记日志 + 返回安全的兜底」,绝不让一个异常把整条链带下去。

--------------------------------------------
## 3.5 取消:AbortSignal

JS 没有「杀掉线程」这种操作,靠的是一张「取消信号票」:AbortSignal。

    const ctrl = new AbortController()
    fetch(url, { signal: ctrl.signal })
    ctrl.abort()                       // 这个请求会以「已取消」失败

项目里 agent 钩子拿到的就是这个东西(roleplay-host.mjs 的 pre-step):

    ctx.on('agent/pre-step', async ({ agent, turn, step, signal }, next) => {
      ...
      if (decision.kind === 'reject' || (signal && signal.aborted)) return decision
    })

signal 已经 abort 的话,这段就直接透传,不再做事。

## 3.6 定时器

    setTimeout(fn, 1000)        // 1 秒后执行一次,返回 id
    clearTimeout(id)            // 取消
    setInterval(fn, 300)        // 每 300 毫秒执行一次
    clearInterval(id)           // 取消

项目里两种都有:扮演引擎的心跳每 60 秒检查一次;桌宠的 drain 每 300 毫秒看看有没有新请求。

【C++ 老习惯会坑你】定时器**不会被 GC 收掉**,忘了 clear 就一直跑;
而且「每 300 毫秒」是「至少 300 毫秒」,主线程忙的时候会延后,别拿它当精确计时。

## 3.7 一小段真实代码,逐行读

    chatPoll: async (args) => {                       // 声明:这是个异步函数
      adoptAgent(args)                                // 先确认要读哪个会话(同步)
      await ensureLoaded()                            // 需要的话先把状态读进内存
      const session = currentSession()
      if (!session) return { messages: [], lastSeq: 0 }   // 兜底:没有会话就给空结果
      const since = Number(args && args.since) || 0   // 上次看到的序号,防脏输入
      return pickMessages(session.events, since, 200) // 纯函数:抽出比 since 新的消息
    }

四个点值得学:异步函数里可以混同步代码;每一步都可能要兜底返回;
对外来的参数先转换再使用;真正干活的挑了个纯函数(好测试、好推理)。

## 这一章记住三件事

1. 单线程 + 事件循环:别阻塞,顺序靠 await;
2. await 要配 try/catch;循环里的 await 别用 forEach;
3. 取消靠 AbortSignal,定时器用完要 clear。
